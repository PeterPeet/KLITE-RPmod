## Goal
Play a whole session from the chat box: **slash commands** (`/go`, `/buy`, `/accept` …) and
one-click **quick replies** do what the chat tags do, through the same engine rules; the tags
can be **hidden** in the displayed chat; a world **round-trips as a lorebook** (SillyTavern /
V2 / V3 / Esolite); summaries use **Esolite's own** memory tools.

## How Esolite does it today (read in `../esobold/embd_res/klite.embd`, 2026-09-25)

### Slash commands = "custom tools"
- **Storage:** `localsettings.custom_tools` — an array of `{ name, description, parameters (JSON
  schema), functionBody (JS source), userCallable }` plus `custom_tools_AI_enabled`. They are
  **settings, not story data**: `generate_savefile` blanks both in the story file. Edited in the
  "Custom Tools" dialog (`show_customtools`, `customtools_done` writes the list back), exported
  as `custom_tools.json`.
- **No other registry.** Every submit re-reads `customtools_sanitize_list(localsettings.custom_tools)`;
  there is no built-in or "extra tools" list. The only way to add a tool is to write into the
  **user's own list** (it would then show in their dialog, be exported with their tools and be
  evaluated from a source string with `new Function`), or to wrap `customtools_sanitize_list`
  (which the dialog and the AI's tool list also use, so our tools would leak into both).
- **Dispatch** is at the top of `prepare_submit_generation()` (a plain, wrappable function; the
  `const submit_generation` is never reached): the input `/name …` is matched **exactly** against
  the names of tools with `userCallable`; `parse_slash_command(tool, text)` splits the rest on
  whitespace/commas into the schema's parameters (positional or `name=value`, quotes and
  brackets group; extra words are dropped as a "trailing comment" — so a multi-word name needs
  quotes: `/move "Forest Road"`), `customtool_coerce_arg` converts types, and
  `TrustedCustomToolCallPromise` runs the function.
- **Result:** the input box first shows "Slash command (/x) activated, please wait…", then the
  tool's **return value replaces the input text** (or "…executed successfully."); parse errors
  go to `msgbox`, runtime errors into the input box. Nothing is generated. (In the aesthetic /
  corpo chat UIs, `chat_submit_generation` copies `cht_inp` into `#input_text` and clears
  `cht_inp` after the call, so the result lands in the hidden classic box.)
- **The AI** can call the same tools by tool calling when `custom_tools_AI_enabled` (MCP-style
  server `custom_tools`).
- RPmod's context wrapper already skips turn processing for these (`isHostSlashCommand`).

### Display pipeline
- Every non-edit render of the story passes each message through
  **`apply_display_only_regex(text)`** (classic mode for the whole text; instruct/aesthetic/
  messenger/corpo through `repack_postprocess_turn`). It applies the user's regex rules marked
  "display only" (`localsettings.regexreplace_data[i].d`), removes `<t2i>` segments and folds
  thinking blocks. The text arrives HTML-escaped (`&lt;move&gt;`) mixed with Esolite's own markup.
- With **Allow Editing** on, the raw text is shown (no display regex).

### Summaries / memory
- **AutoGenerate Memory** (`autogenerate_summary_memory()`, button in the Context/Memory dialog
  `btn_memory()`): summarises the story with the current backend and writes
  `[Summary: …]` into the dialog's Memory box; the user confirms with OK.
- **Running memory** (`localsettings.enableRunningMemory`, Esobold setting, experimental): every
  minute, when enough new text exists, a summary becomes a constant WI entry in the group
  "Autogenerated history" (at most 5).
- TextDB / RAG for long stories.
- RPmod's Context panel still has its own "Smart Memory Writer" (older; generates into its own
  box). Not extended in R6.

### Lorebooks
- Import: SillyTavern World Info files (`entries` keyed by `uid`) via `load_tavern_wi`, V2 cards'
  `character_book`, NovelAI, AI Dungeon, Agnai; optionally into TextDB.
- Export: the flat WI array (`export_wi_to_file`), and a card's `character_book` from a WI group
  (Esobold's character editor).
- Esolite's **Library** stores lorebooks as records of type "World Info"
  (`saveLorebookToIndexDB(name, wiArray, original)`), which Quick Start can load.

### Quick replies
Esolite has none. RPmod has five **Quick Actions** (Tools panel, stored per browser as
`rpmod_adv_actions`, sent as a chat message) and five Auto Sender "quick slot" messages.

## Decisions
1. **RPmod commands are not written into the user's custom tools.** Writing there would put
   RPmod code into the user's settings/exports and their dialog, and would expose every command
   to the AI's tool calling. Instead RPmod wraps `prepare_submit_generation` (outermost, like
   Esolite's own slash check sits at its top) and handles **only its own command names**; any
   other `/…` text goes on to Esolite unchanged. **A user tool with the same name wins** (RPmod
   steps aside), so nothing the user built stops working. The context wrapper also treats RPmod
   commands as "not a turn", whichever wrapper ends up outside.
   *Possible later Esobold PR:* a small registry for mod slash commands (like the Quick Start /
   Settings / Guide hooks). Not needed now.
2. **Same look and feel as Esolite's slash commands:** typed in the same input box, `/name args`,
   errors in Esolite's `msgbox`, nothing generated by the command itself.
   **Different argument rule, on purpose:** the rest of the line is the argument, so names with
   spaces need no quotes — `/go Forest Road`, `/buy Bram: Torch x2` (the same text as inside the
   chat tag). Esolite's whitespace splitting would cut "Forest Road" to "Forest".
3. **Commands go through the engine, like the tags.** Each command calls the Worlds API (or
   `applyTags` with the equivalent tag), so the rules decide exactly as for the AI's tags. The
   result is written to the **game log**, which the AI reads on its next turn ("AI narrates,
   software adjudicates"). A command changes state immediately and generates nothing; press Send
   (empty box = let the AI continue) or write a message to get the narration.
4. **Chaining:** a line may hold several parts separated by ` | ` and a message may have several
   lines. Parts starting with a known `/command` run first, in order; everything else is sent as
   the chat message afterwards: `/go Forest Road | I set off before dawn.` A failed command stops
   the rest (nothing is sent), like a failed tool.
5. **Feedback:** what a command logged is shown in a short toast; info commands (`/look`, `/inv`,
   `/help` …) show their text in Esolite's `msgbox`; window commands open RPmod windows
   (`/quests`, `/shop`, `/map`, `/lookup Fireball`, `/sheet`).
6. **Quick replies build on the Quick Actions.** A reply = `{ label, text, send }`; `text` uses the
   same syntax as the chat box (commands, ` | `, a message). The five Quick Actions become the
   first five replies (migrated once; the old key is left in place). Clicking a reply runs its
   commands and sends its message (`send: true`) or puts the message into the input box.
   Shown as a **left-dock section "Quick replies"** (one click while chatting, no DOM injected
   into Esolite's several input layouts), with an edit mode. A **"Here" row** adds replies from
   the world state: ways out of the current place, people to talk to, vendors (Shop), quests to
   accept or turn in, Search in a dungeon — so a session can be played by clicking.
7. **Hiding tags is a display setting** ("Hide control tags in the chat", section Display,
   default **off**). RPmod wraps `apply_display_only_regex` and removes the RPmod tags from the
   displayed text only: the story text keeps them, the engine parses them as before, Allow
   Editing shows them. The game log shows what they did.
8. **Lorebook round trip.** Export a world as a **SillyTavern World Info / Esolite lorebook**
   (`entries` keyed by `uid`, with both `key`/`keys` and `keysecondary`/`secondary_keys`, so
   SillyTavern and Esolite's own importer read it) or as a **Lorebook V3**
   (`{ spec: 'lorebook_v3', data: { entries: [] } }`), besides the World JSON and the flat
   Esolite WI array. Each entry carries `extensions.rpmod = { kind, id }` and a header line
   (`[Location: Brookvale]`); the book carries the whole world in `extensions.rpmod.world`.
   Import: a book with an embedded world restores it (new id if that id is taken — never
   overwrite a world) and then applies text edits made to its entries elsewhere; entries without
   RPmod data become lore; a plain book's entries become typed nodes when they carry the RPmod
   data or header, else lore (as today). "Save to Esolite's Library" stores the book as a World
   Info record there (Esolite's own function), so Quick Start can load it.
9. **Summaries: Esolite's.** `/summary` opens Esolite's Context dialog and starts its
   AutoGenerate Memory (the user confirms with OK, as with the button). The User Guide points to
   Esolite's running memory. RPmod builds no summariser of its own.

## Commands → engine
World commands need an enabled world ("No world is active" otherwise). `persona` = the Tools
panel's persona; checks use its sheet.

| Command | Does | Engine |
|---|---|---|
| `/go <place \| direction>` (`/move`) | go somewhere (doors, rooms, towns) | `W.go(target, { source: 'ui' })` |
| `/look` | where you are, ways out, people, objects | `W.previewSlice()` (what the AI sees) |
| `/search` | search the room (Perception/Investigation roll) | `W.search({ source: 'ui' })` |
| `/open`, `/close`, `/unlock <door>` | doors | `W.door(action, target, { source: 'ui' })` |
| `/talk <person>` | speak with someone ("talk" objectives) | `<talk>` |
| `/give <item> [xN]`, `/take <item> [xN \| x all]` | inventory | `<give>`, `<take>` |
| `/inv` | inventory and purse | `W.inventory()` |
| `/buy [vendor:] <item> [xN]`, `/sell …` | trade with a vendor here | `<buy>`, `<sell>` |
| `/shop` | Shop window | shell `shop` |
| `/accept <quest>`, `/turnin <quest>`, `/abandon <quest>`, `/track <quest>` | quests | `W.acceptQuest`, `<turnin>`, `W.abandonQuest`, `W.setActiveQuest` |
| `/quests` (`/quest` without `=`) | Quest log window | shell `questlog` |
| `/quest <id>=<state>` | set a quest state (creator) | `<quest>` |
| `/rep` · `/rep <faction>=±n` | standings · change one | `W.reputation()` · `<rep>` |
| `/roll <dice> [adv\|dis]` | roll and log | `KLITE_RPMod_Log.rollAndLog` |
| `/check <ability\|skill> [DC] [adv\|dis]` | the persona rolls a check | sheet bonus (`derive`) → log |
| `/attack <target> [weapon]` | attack in a fight | `W.attack('__player__', …)` |
| `/encounter <saved \| monsters>` | start a fight | `<encounter>` |
| `/endturn`, `/rest` | next turn · long rest | `W.nextTurn()` · `W.longRest()` |
| `/time <slot>`, `/advance [n]`, `/weather <text>` | clock | `<time>`, `W.advanceClock`, `<weather>` |
| `/flag <key>[=value]`, `/unflag <key>`, `/action <text>` | story flags, action triggers | `<flag>`, `<unflag>`, `<action>` |
| `/map`, `/combat`, `/sheet [name]`, `/lookup <query>` | open windows | shell / Characters / Compendium |
| `/summary` | Esolite's AutoGenerate Memory | `btn_memory()` + `autogenerate_summary_memory()` |
| `/help [command]` | list / explain commands | — |

Arguments must not contain `<` or `>` (they would break the tag); they are removed.
If a command logs nothing itself (e.g. `<give>`), RPmod logs one line for it, so the AI learns
what the player did.

## UI
- **Chat box:** type commands; `/help` lists them. Toast with the result.
- **Left dock → "Quick replies":** a row of buttons (the player's replies) and the "Here" row;
  a pencil switches to edit mode (label, text, "send" toggle, add/remove/reorder). Stored per
  browser (`rpmod_quick_replies`, like the Quick Actions). The Tools panel's Quick Actions
  section points to the new section.
- **Settings → RPmod → Display:** "Hide control tags in the chat"; "Show the Here row".
- **World tab → Export:** World JSON · Lorebook (SillyTavern / Esolite) · Lorebook V3 · Esolite
  WI array · Save to Esolite's Library. **Import** accepts all of them.
- **Guide:** the "Changing the world from chat" chapter gains the commands and quick replies.
